# 04 · 指令微调（SFT）：教会它"对话"

## 目标
在预训练模型上，用 90 万轮对话数据教会它：
认 chat template（system/user/assistant 标记）、听懂指令、像助手一样答话、
会写 think 思考块。SFT 后模型从"续写机器"变成"对话模型"。

## 核心概念
1. **格式即能力**：SFT 本质还是 next-token prediction，
   只是数据换成了"渲染过 chat_template 的对话"。
   01 阶段学的 template 在这里变成训练信号。
2. **loss mask（关键）**：只对 assistant 的 token 算 loss，
   user/system 部分 label 置为 -100（ignore_index）。
   为什么：我们只希望模型学"怎么回答"，不学"怎么提问"。
3. **思考模式**：SFT 数据带 reasoning_content 字段，
   渲染成 think...think结束 块。模型学会"先想后答"。
   推理时 open_thinking 参数控制要不要思考块。
4. **小学习率**：SFT 用 1e-5~5e-5（预训练的 1/50），
   目的是"塑造格式"而不是"重写知识"——太大会灾难性遗忘。
5. **数据量**：90 万条已经很多，0.5B 用 1~5 万条高质量子集 + 1~2 epoch 就够，
   先跑子集迭代快，最后可以全量再压一遍。

## 数据事实
- sft_t2t_mini.jsonl：1.7G / 905,718 条 / conversations 格式
- 每条 = user/assistant 交替，assistant 可带 reasoning_content
- 来源：minimind 官方 SFT 数据（dl_sft.log 可查下载来源）

## SFT 配置（拟定）
| 项 | 值 |
|---|---|
| 底座 | 03 阶段的 best 预训练权重 |
| 数据 | 先抽 2 万条子集（按长度分层抽样，E1 写脚本） |
| seq_len | 1024（对话 + 思考块比预训练长） |
| 有效 batch | 32~64 |
| lr | 2e-5 cosine |
| epoch | 1~2 |
| 步数 | ~600~1200 步（子集），约 2~4 小时 |

## 实验任务
- **E1 数据子集**：写抽样脚本（分层：按对话轮数/长度分桶），
  产出 sft_subset_20k.jsonl，统计轮数分布、长度分布。
- **E2 迷你 SFT**：2 万条子集跑 1 epoch，全程约 2~4 小时。
- **E3 人评盲测**：SFT 前后各用 10 个固定问题对话（同一随机种子），
  对比：格式对不对（有没有按 template 回）、答非所问率、思考块质量。
  结果表格贴 notes。
- **E4 失败案例集**：收集 20 个 SFT 后仍回答不好的 case → 这是
  05 阶段 DPO 偏好数据的天然来源（留好！）。

## 验收标准
1. 对话格式正确率 > 95%（盲测 20 轮，贴样本）
2. 能解释 loss mask 的实现细节
3. 失败案例集 ≥ 20 条
