# 05 · 性格对齐（DPO）：给模型注入人格

## 目标
SFT 教会了模型"怎么说"，这个阶段决定"它是谁"：
用偏好数据（chosen / rejected 回答对）+ DPO 算法，
把 0.5B 模型塑造成一个有固定性格、口癖、价值观的小角色。

## 核心概念
1. **偏好对**：同一个问题下，chosen = 符合人设的好回答，
   rejected = 不符合人设的坏回答。模型学到"前者概率 > 后者概率"。
2. **DPO 为什么不用奖励模型**：PPO 路线要先训 reward model 再 RL，
   工程复杂、显存大；DPO 把 reward 优化解析掉，直接对偏好对做
   类似 SFT 的训练（一个二分类 loss），单卡可跑，特别适合 0.5B。
3. **DPO loss 直觉**：拉大 policy(chosen) 与 policy(rejected) 的 log 概率差，
   同时用 reference model（SFT 权重冻结副本）防止跑太远（beta 控制强度）。
4. **性格从哪来**：
   - 人设 system prompt（名字、性格、口癖、世界观、说话规则）
   - 偏好数据里 chosen 的人设一致性
   - DPO 的 beta / lr 控制"改多少"
5. **人设工程**：给 0.5B 写人设要具体、可执行、带例子
   （"你是个 30 岁的猫娘程序员，说话带喵，回答代码问题先吐槽再给方案"），
   空泛的"友好、专业"小模型学不出来。

## 数据准备路线（我们的数据是 04 的副产品）
1. 从 04 的失败案例集 + 正常案例里，对每个 prompt 用 SFT 模型
   temperature=0.9 采样 4 个回答
2. 按"人设一致性"打分（先规则 + 人工抽审，后期可以用大模型当裁判）
3. 取最好/最差构成偏好对 → 目标 2000~5000 对（0.5B 够用）

## DPO 配置（拟定，用 minimind train_dpo.py）
| 项 | 值 |
|---|---|
| 底座 | 04 阶段 SFT 权重（同时作为 reference model） |
| 偏好对 | 2000~5000 对 |
| seq_len | 1024 |
| 有效 batch | 16~32 |
| lr | 5e-6~1e-5（比 SFT 再小） |
| beta | 0.1~0.5（先 0.1） |
| 步数 | ~500~1500 步，约 1~3 小时 |

## 实验任务
- **E1 人设定稿**：写 3 个候选人设（见 08_zz_agent 的候选清单），
  各配 10 条示例对话，人评投票定 1 个。
- **E2 采样 + 打分**：按上面的数据路线造 3000 偏好对。
- **E3 DPO 训练**：跑 3 组（beta 0.1 / 0.3 / 1.0），对比人设漂移程度。
- **E4 性格盲测**：30 个日常问题，对比 SFT 版 vs DPO 版，
  按"人设一致性 / 趣味性 / 不出戏"打分，贴 notes。

## 验收标准
1. DPO 版盲测"人设一致性"显著高于 SFT 版（贴对比样本 ≥ 10 组）
2. 偏好数据管线可复现（脚本 + 数据在仓库）
3. 能讲清 DPO loss 每一项的含义
