# L2 · 容量分配：500M 怎么分

> 目标：给定 C1 预算 500M（450~550M）、V=6400，定出 (H, L, I)，再对显存/速度/长上下文算账。
> L1 §7 只证明了"这套数加起来 = 0.5B"，本节回答"为什么是这套而不是别的组合"。

## 0. 工具：参数公式

设 H=hidden，L=层数，I=intermediate，r=Q头/KV头=2（GQA 16:8）：

| 项 | 公式 | 代入 1280/4032 |
|---|---|---|
| 每层 attention（含 q/k_norm，可忽略） | A = 2H²(1+1/r) = **3H²** | 4.91M |
| 每层 FFN（SwiGLU 三矩阵） | F = **3·H·I** | 15.48M |
| embedding（与 lm_head 共享，只算一次） | E = **V·H** | 8.19M |
| 总量 | N = V·H + L·(3H² + 3HI) | **497.8M** |

## 1. 先定形状：attention 与 FFN 的配比

两个直觉：
1. **attention = 混音器**（token 间交换信息），**FFN = 知识库**（逐 token 存取事实/格式/模式）
2. 现役模型经典配比 attn:ffn ≈ **1:3~3.5**（LLaMA/Qwen 一致）：钱最多花在知识库上

配比公式（r=2 时）：`F/A = I/H`——所以 4032/1280 ≈ **3.15**，
而 minimind 源码里 `I = ceil(H·π/64)·64` 的 π≈3.14 就是这套配比的经验系数，根本不是拍脑袋。

## 2. 三套候选（都填满 ~500M）

| 方案 | H | L | I | A/层 | F/层 | 单层 | attn:ffn | 总量 |
|---|---|---|---|---|---|---|---|---|
| A 宽而浅 | 1536 | 18 | 4416 | 7.08M | 20.35M | 27.4M | 1:2.9 | ~504M |
| **B 均衡 ✅** | **1280** | **24** | **4032** | **4.91M** | **15.48M** | **20.4M** | **1:3.15** | **497.8M** |
| C 深而窄 | 1024 | 32 | 4032 | 3.15M | 12.39M | 15.5M | 1:3.9 | ~504M |

推导（以 B 为例自洽性检查）：490M÷24 层 = 20.4M/层 → F/A=3.15 →
A≈4.9M → H=√(4.9M/3)≈1280 ✓ → F≈15.5M → I=F/(3H)≈4032 ✓ —— 数字自己咬合。

## 3. 为什么选 B（对 A / C 的裁决）

1. **我们的任务是"多步链"**（思考→调工具→看结果→再想；SFT/RL 阶段 long context），
   需要的是**深度优先**：顺序变换步数越多，越能承载长链路推理。
2. **C 的注意力太薄**：attn 只占 1:3.9，token 间交互是瓶颈——而工具调用/多轮对话
   恰恰是"长程交互密集型"。C 的 32 层"步骤多，但每一步的混音带宽不足"。
3. **A 浪费在 attention 的平方上**：H² 让混音器吸走预算，深度反而拉到 18 层；
   单步再强也架不住"想 18 步就断了"。
4. **B 是验证过的密度**：24 层 × 20.4M 是 0.5B 档最常用组合（Qwen2.5/Qwen3-0.5B 都是 24 层），
   配比 1:3.15 与 LLaMA-7B（32 层，1:3.2）同族等比缩小——**别发明比例，用被训过几十亿次验证的**。

## 4. 拍板后的全部账单

- **参数**：497,812,480 ≈ **497.8M**（C1 ✅，偏差 0.44%，留 0.4% 余量）
- **分布**：embedding 8.19M（1.6%）+ 24×(attn 4.91M + ffn 15.48M) + final norm 1,280
- **训练计算量**：FLOPs = 6·N·T ≈ 6×497.8M×1.5B ≈ **4.5e18**；
  2×4090 bf16 DDP 实际 ~70~120 TFLOPS → 理想 12~20h，留冗余 → **15~28h** ✓（与 03 阶段估算互证）
- **训练显存**（bf16 全参 DDP，seq 512，micro-batch 8~16）：权重系 ~8G/卡 + 激活，24G×2 宽裕 ✓
- **推理 KV cache**（32k 上下文，GQA-8）：1.88G/条（MHA 会是 3.75G，L1§1 已算）
- **层数为何是 24 不是 20/26**：20 层 = 400M，预算没用满（亏 100M 的能力）；
  26 层 = 538M 也合法但贴近上限、留 margin 不足；24 层 = 489.6M + 8.2M ≈ 497.8M
  恰好贴近 500M 又留余量，且是 0.5B 档最少量的已验证值。

## 5. 边界防线（为什么不再宽/再窄/再深/再多头）

- 更宽 H≥1536：attention/embedding 涨得快（H 一次方×2 处 + H² 一处），FFN 被挤 → 知识库饿死；
  且单步贵、RL rollout 每步都慢。
- 更窄 H≤768 + 更多层：每层 attn 只剩 ~1.8M，混音带宽不足；层多 → 延迟长。
- 头数再翻倍 32：head_dim=40 太细，注意力质量退化（共识 head_dim≥64）。
- 词表更小：01 已锁 6400（C3），不重训。

## 6. 风险声明

- **已知欠训练**：497.8M 配 1.5B token（首版）≈ 3× Chinchilla 最优（~150M）。
  有意为之：任务要的是格式+人设+少量推理，不是百科全书；先"会说话+按格式"，
  跑通后如需可吃满 03 全量语料（4~5B token）补训一轮，人类评测对比后再定。
- **若 SFT/RL 显存吃紧**：seq 降到 1024 或开 gradient checkpointing，**不动架构**。
